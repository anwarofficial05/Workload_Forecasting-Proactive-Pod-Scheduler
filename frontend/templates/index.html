Existing System Limitations

  • Reactive Single-Metric HPA: Scales only after CPU crosses a static threshold, causing inherent delay while pods boot up.
  • Latency Spikes & SLO Breaches: Sudden traffic bursts arrive while pods are still pending, leading to queuing and timeouts.
  • Isolated Placement: Default scheduler ignores predicted future node load and multi-criteria goals (latency, memory, cluster balance).
  • Single-Model Lag: Existing approaches use LSTM alone, which smooths out sharp spikes and lacks placement integration.

Proposed Novel Solution

  • LSTM + XGBoost Ensemble: LSTM tracks sequential temporal trends; XGBoost captures non-linear jumps and sudden derivatives.
  • Multi-Objective Node Ranking: Scores candidate worker nodes simultaneously on CPU headroom, memory headroom, latency, and load balance.
  • Proactive Warm Pod Placement: Deploys and warms pods 1-2 minutes before traffic peaks, preventing SLO violations entirely.
  • Production Kubernetes Extender: Direct drop-in compatibility with standard K8s Scheduler Extender webhook specification.

Ensemble Fusion Architecture

Pure LSTM networks suffer from sudden-spike prediction lag because sequential recurrence inherently smooths sudden bursts. By fusing PyTorch LSTM (capturing long-term temporal dependencies) with XGBoost (trained on engineered first and second derivative rate-of-change features), the ensemble instantly detects sudden traffic spikes, providing an accurate, jitter-free forecast ahead of demand.
